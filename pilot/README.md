# Карты Таро — закрытая тестовая интеграция VK Mini Apps

**Статус:** эксперимент, не опубликовано в VK и не подключено к работающей версии.

## Что находится в ветке

- `pilot/index.html` — отдельная мобильная страница, не заменяющая `index.html`.
- `pilot/client.js` — запросы подписанной сессии к независимому серверу.
- `pilot/style.css` — оформление. Никакие файлы интерфейса работающего приложения не заменены.
- `tests/pilot.spec.mjs` — браузерный тест с настоящими HTTP-запросами к локальному API + SQLite.
- `.github/workflows/tarot-v2-vk-pilot.yml` — автоматический запуск Chromium в мобильных размерах.

## Безопасный алгоритм

1. ВК открывает тестовый адрес в контексте **того же VK-приложения 54582199**. В URL есть `vk_app_id`, `vk_user_id`, `vk_ts` и `sign`.
2. Страница загружает VK Bridge и сохраняет подписанные значения **только в оперативной памяти**. После чтения удаляет их из адресной строки через `history.replaceState`.
3. Вызовы `VKWebAppInit` и `VKWebAppGetUserInfo` должны завершиться успешно. Полученный ID сравнивается с ID из параметров запуска. Это дополнительная клиентская проверка, **не авторизация сама по себе**.
4. Сервер отдельно проверяет подпись HMAC, ID приложения и срок запуска. Только после ответа 200 разблокируются кнопки.
5. Награда и карта дня запрашиваются через POST **без тела**. Игровые числа и идентификатор аркана выбираются сервером. Отчёт показывает серверный прогресс.
6. Неверная/истёкшая подпись, отсутствие SDK, несоответствие VK Bridge или ошибка сети блокируют действия без перехода в деморежим.

## Важные ограничения

- Нужны настоящий защищённый ключ VK **только на сервере**, постоянное хранилище SQLite и HTTPS-хостинг тестовой страницы. Не добавлять ключ, любые access token, куки или полную подписанную строку запуска в GitHub, сообщения чата, логи или аналитические системы.
- Страница обращается строго на **свой домен** (`/api/v1/*`). Для другого сервера нужен доверенный reverse proxy на том же домене. API-адрес нельзя подменить через URL-параметр.
- При ручном обновлении страницы параметры запуска уже удалены из адреса, поэтому доступ будет закрыт. Требуется заново открыть тестовую страницу из ВК. Это намеренный безопасный режим пилота.
- Строка запуска первоначально попадает на хост, где расположена страница. **Отключите логирование query-строк на веб-сервере и proxy**, включая аварийные и access-логи. Referrer-Policy: no-referrer предотвращает пересылку строки в Referer.
- Используется тот же внешний SDK VK Bridge, что уже указан в действующем коде, но при его недоступности никаких серверных действий не выполняется. Нельзя считать браузерный мок реальной проверкой работы внутри мобильного ВК.
- Даже подписанная сессия действительна ограниченное время. Это не полноценный долгоживущий вход; для продакшена потребуются безопасное обновление/переподписание сессии, rate limit, HTTPS reverse proxy, резервные копии, аудит и модель миграции с существующих VK Storage ключей.
- **Нельзя менять адрес действующей версии приложения** ради проверки. Используйте отдельный *адрес для разработки* VK (если доступен и поддерживается настройками) либо отдельное тестовое приложение/контекст с корректной серверной конфигурацией. Для отдельного app ID требуется соответствующее значение в серверной конфигурации и корректные подписи, нельзя просто открыть страницу с другой ID.
- Кристаллы и арканы пилота пока не объединены с историей/балансом у прежних пользователей. Это специально, чтобы избежать ошибочной миграции и дублирования.
- Нет рекламы за вознаграждение, покупок или денежных начислений. Нельзя подключать оплату без отдельного аудита.

## Локальная автоматическая проверка

CI использует **только вымышленный тестовый HMAC-ключ**. Он не связан с реальным приложением.

- Node 24 с SQLite запускает сервер на localhost:8787.
- Python поднимает статические файлы на localhost:8765.
- Playwright маршрутизирует браузерные запросы к API на настоящий localhost-сервер. Тело ответа получает от SQLite, а не от заглушки.
- Действия VK Bridge в тестах **имитируются**, потому что GitHub Actions не является клиентом ВК. Это проверка клиентского контракта, не подтверждение в реальном VK.
- После проверки смотрите артефакт GitHub Actions с тестовыми скриншотами. Только после реального VK WebView UAT рассматривайте перенос на тестовый стенд.

## Проверки перед запуском в ВК

Проверить: правильный идентификатор приложения, адрес разработки, HTTPS, CORS, отсутствие ключей в репозитории, отключение логов query-параметров, работоспособность VK Bridge на Android, повторное открытие после истечения токена, отказ от доступа без подписи, резервное восстановление БД.

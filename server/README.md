# Карты Таро · экспериментальный защищённый сервер прогресса

**Без публикации в VK.** Код находится только в feature/tarot-v2-secure-backend. Существующие index.html, engagement.js, progression.js, старые ключи VK Storage и приложение 54582199 НЕ менялись и не подключены к API.

## Что реализовано

- Проверка подписи параметров запуска VK Mini Apps (sign, HMAC-SHA256) серверным защищённым ключом, проверка vk_app_id=54582199, vk_user_id, срока vk_ts (15 минут; допустимо до 60 секунд опережения), запрет дубликатов signed-параметров, сравнение подписей за постоянное время.
- SQLite с транзакцией BEGIN IMMEDIATE и уникальным (user_id, day) для разового начисления ежедневной награды по UTC. Награда: 10,15,20,25,30,35,50 **условных игровых очков**, после пропуска серия обнуляется.
- Карта дня выбирается **сервером**: карточки клиента и client-side Math.random() не используются для защищённого прогресса. На пользователя — один результат за UTC-день. Карта автоматически фиксируется в коллекции.
- GET /health — проверка работоспособности, без персональных данных.
- GET /api/v1/progress — только свой баланс, серия, коллекция арканов, достижения.
- POST /api/v1/daily/claim — ежедневная награда, без тела запроса.
- POST /api/v1/daily/draw — карта дня, без тела запроса.

Запрос к защищённым маршрутам: заголовок Authorization: Bearer [строка-параметров-запуска-VK]; **не передавать подписанные параметры в URL**. Для браузерного API указывать свой доверенный адрес в ALLOWED_ORIGINS. Не сохранять заголовок в логах веб-сервера или аналитики. Нельзя отправлять секрет приложения клиенту.

## Запуск только после самостоятельной настройки

Нужен Node.js **24.15+** и постоянное хранилище SQLite (диск, сохраняемый между перезапусками). Этот прототип не требует npm-зависимостей; используется встроенный модуль node:sqlite (его API в Node 24 имеет статус release candidate).

Пример переменных окружения (это имена, а не реальные секреты):

    VK_PROTECTED_KEY=[секрет-из-настроек-VK]
    VK_APP_ID=54582199
    HOST=127.0.0.1
    PORT=8787
    DB_PATH=/absolute/persistent/path/taro-progress.sqlite
    ALLOWED_ORIGINS=https://your-own-vk-miniapp-host.example

Команды:

    cd server
    node --test test/*.test.mjs
    node src/main.mjs

Запуск с доступом из интернета требует отдельного HTTPS reverse proxy, ограничений частоты запросов, защиты логов, резервных копий и проверки настроек VK. **Не запускать публично до этого.**

## Почему клиент ещё не переключён

Ранее выпущенный клиент держит очки, историю и открытые арканы в VK Storage. Эти данные **нельзя считать доказанными**: их может менять клиент. Не переносить клиентский баланс в защищённый баланс без отдельной политики миграции. В этом этапе старые интерфейсы продолжают работать прежним образом. Серверный прогресс независим, и его можно тестировать без риска потерять историю у пользователей.

**НЕТ** подтверждения рекламных показов, VK Pay, платежей, обмена очков на покупки и серверных платных раскладов. Эти операции не реализованы намеренно, чтобы не открывать незаслуженный доступ. В серверной версии пока есть только бесплатная карта дня и некоммерческие очки.

Для будущего защищённого запуска потребуются корректное подтверждение наградных событий VK, авторизация, атомарные покупки, идемпотентность и аудит. Подпись VK Mini Apps удостоверяет параметры запуска, **но не достоверность клиентского утверждения об успешной рекламе**.

## Исходники

- src/auth.mjs — проверка VK подписи.
- src/store.mjs — транзакционная SQLite модель.
- src/http.mjs — HTTP API с allowlist происхождения браузера, отсутствием доступа по поддельному user_id и минимальными ответами.
- src/main.mjs — запуск при наличии секретов.
- test/security.test.mjs — негативные/положительные тесты.
- .github/workflows/tarot-v2-server.yml — CI только для файлов сервера.

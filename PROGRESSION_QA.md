# Taro V2 — Коллекция арканов и задания

## Ветка и обратная совместимость

- Репозиторий: \`masksimus/CartTaro\`
- Рабочая ветка: \`feature/tarot-v2-progression\`
- Основана на: \`feature/tarot-v2-qa\`
- \`main\` и приложение VK \`app54582199\` не меняются и не публикуются из этой ветки
- \`Test-cart\` не используется
- Основные ключи VK Bridge \`history\`, \`dailyCard\`, \`consent\` не менялись

## Механика

- Новый раздел **Арканы** пятым пунктом нижней навигации (четыре предыдущих позиции сохранены).
- Отображение полного набора 22 Старших арканов, открываются при обычных раскладах.
- Ключ хранения \`taro_arcana_collection_v1\` содержит только массив числовых идентификаторов карт (0–21).
- Коллекция мигрирует из существующей истории раскладов и не сбрасывается при ограничении истории в 50 записей.
- Три задания обновляются ежедневно и определяются по старым историческим записям и уже существующей награде дня:
  - получить карту дня;
  - выполнить любой расклад;
  - получить ежедневные кристаллы.
- Шесть достижений: первая карта, 5, 10, 22 уникальных карты, 3 и 7 дней серии.
- Внутри модуля нет покупок, внешних API или платной валюты. Кристаллы остаются счётчиком прогресса, не платёжным активом.

## Обработка ошибок

- Показ коллекции не блокирует расклады; \`progression.record\` не ожидается основным приложением.
- При невозможности сохранить коллекцию пользователю выводится предупреждение; при повторном открытии данные по возможности восстанавливаются из истории.
- Новые функции и стили в \`progression.js\`, \`progression.css\`. Их можно убрать вместе с семью подключениями/вставками в \`index.html\`.
- Не менять существующие алгоритмы выбора карт и рекламу в рамках этого этапа.

## Автоматические тесты

GitHub Actions \`Tarot V2 Mobile QA\` запускает Playwright с эмуляцией мобильного Chromium при ширине 320, 360 и 393 CSS px.

Тестовые сценарии:
1. Исторические: первый запуск, согласие, карта дня, реклама в демо-режиме, история, вкладки, сохранение ежедневной награды.
2. Коллекция: открытие первого аркана и результатов трёхкарточного расклада, отсутствие дублирования одинаковых карт.
3. Все три задания с завершением после реальных событий.
4. Все шесть достижений отображаются, успех по первому открытому аркану.
5. Сохранение коллекции после перезагрузки; перенос из старой истории; сохранение при удалении старой истории.
6. Работа интерфейса без внешних CDN и правильная прокрутка до последней карточки коллекции.
7. Скриншоты, HTML-отчёт и трассы сохраняются в артефактах GitHub Actions.

## Обязательные проверки перед слиянием / публикацией

- Проверить фактический рендер всех вкладок в **клиенте VK для Android**.
- Проверить VKWebAppStorageGet / VKWebAppStorageSet для ранее существовавших пользователей на реальных VK-аккаунтах.
- Проверить восстановление истории после обновления и при повторном входе на другом устройстве.
- Проверить карту дня в переходе через полночь и серии дней при нестабильной локальной дате.
- Проверить расклады, отказы рекламы, отсутствие интернета, шрифты, изображения и доступность.
- Серверная проверка прогресса необходима **перед** привязкой кристаллов/достижений к платным действиям. Не использовать это клиентское хранилище как финансовый реестр.

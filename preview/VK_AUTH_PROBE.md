# Карты Таро — VK authorization readiness / read-only preview

## Статус

Изолированная проверка возможности авторизовать VK Mini Apps запуск через Vercel Node.js Function. **НЕ реальная игровая версия**, **НЕ живые платежи**, **НЕ сохранение игрового прогресса**. Оригинальное приложение `54582199`, `main` и `tarotpreview2026.vercel.app` остаются без изменений.

Состав:
- `api/vk/status.mjs` — публичный безличный статус, не раскрывает секрет.
- `api/vk/verify.mjs` — POST, Authorization Bearer со штатными VK signed launch-параметрами. HMAC-SHA256, vk_app_id, user_id, время запуска проверяются на сервере с существующим `server/src/auth.mjs`.
- `preview/vk-status.html` и `preview/vk-status.js` — только UI-проверка готовности по GET `/api/vk/status`.
- `server/test/vercel-vk-auth.test.mjs`, `tests/vk-status.spec.mjs` и отдельный GitHub Actions workflow.

## Как включить реальную проверку подписи, когда тестовый адрес в VK готов

1. В Vercel открыть **Project → Settings → Environment Variables** для `tarotpreview2026`.
2. Создать **`VK_PROTECTED_KEY`**, значение — только официальный protected key того приложения ВК, для которого будет тестироваться HMAC. Выбрать **только Preview**; не добавлять в Production, Development, GitHub или чат. При наличии режима Sensitive/Encrypted выбрать его. Не передавать ключ в клиентские страницы и не публиковать в логах.
3. Создать **новый Preview deployment** после сохранения переменной; существующие деплойменты не обновляются автоматически.
4. Открыть `https://<preview-host>/vk-status.html`. Статус `configured: true` означает только готовность к проверке, **не подтверждение полноценного входа**.
5. Только после настройки официального **тестового URL внутри ВК**, без замены URL основной версии, проверить настоящий launch-parameter token в контексте VK WebView через строго same-origin POST с `Authorization: Bearer <подписанные vk_... параметры>`. Не помещать параметры в URL API, логи, письма, баг-репорты и этот чат.
6. Защищённая функция отвечает `200 {verified:true,appId:54582199}` для действительной подписи, `401 unauthorized` для неверной или устаревшей, `503 auth_not_configured` если ключ отсутствует, `403 origin_denied` для чужого веб-источника. Пользовательский ID в ответе отсутствует.

## Важные ограничения

- В Vercel проекте не обнаружено подключённого постоянного хранилища. **Никаких ежедневных бонусов, кристаллов, прогресса, коллекций и транзакций в этих функциях нет**. Для серверной экономики нужен постоянный Postgres/Redis с защитой от повторных начислений или отдельный VPS с уже проверенным SQLite из `feature/tarot-v2-staging`.
- Проверка подписи не должна считаться защитой от повторного использования одного запуска в течение TTL: до игрового продакшена нужны одноразовые серверные сессии, лимиты, защита от повторов и политика хранения.
- Параметры подписанного запуска живут не более 15 минут, будущие timestamp более 60 секунд отклоняются.
- В этом этапе браузер не отправляет параметры VK вообще: тестируется только готовность и серверный контракт в CI, пока настоящий тестовый URL ВК и protected key отсутствуют.
- Никогда не менять текущий URL опубликованного приложения ради эксперимента.
- Vercel Preview может потребовать вход владельца (Deployment Protection). Если из браузера открывается окно Vercel Authentication, это защита платформы, а не ошибка HMAC. Не отключать защиту без отдельного решения.

## QA

Запуск:
```
node --test server/test/*.test.mjs
npx playwright test --config tests/playwright.config.mjs vk-status.spec.mjs
```

CI работает **только с искусственным** `TEST_ONLY_VK_PROTECTED_KEY_FIXTURE_DO_NOT_USE`. Результат теста не подтверждает вход пользователя в настоящий VK WebView.

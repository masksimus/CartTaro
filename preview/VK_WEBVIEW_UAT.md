## Что ещё требуется для настоящего VK WebView UAT

1. Настройки проекта Vercel -> Security / Deployment Protection. Текущий preview-домен закрыт Vercel Authentication; внутри VK WebView это не сработает как обычная публичная страница. Если тариф/панель разрешают **Deployment Protection Exception**, добавьте исключение только для домена конкретной тестовой preview-сборки, сохранив защиту остальных развёртываний. Не отключайте защиту всего проекта и не меняйте production-домен. Защита самой API-пробы должна оставаться за HMAC-подписью.
2. Проверьте вне VK, что тестовый \`/vk-login.html\` открывается без Vercel Authentication (в обычном браузере он должен показать инструкцию «Откройте … через настройки разработчика» — это ожидаемо), а \`/api/vk/status\` показывает \`configured: true\` без раскрытия значения ключа.
3. В \`dev.vk.com\` зайдите в своё приложение с ID \`54582199\`. Найдите **URL для разработки** / **Development URL** (VK предоставляет отдельный адрес разработчику/администраторам). Установите туда именно \`https://tarotpreview2026-oq4cmb85i-maksimiirina1992-9738s-projects.vercel.app/vk-login.html\`. **Не изменяйте основной URL приложения, Web/IFrame URL или URL для пользователей.**
4. Откройте приложение как администратор внутри официального клиента VK; VK добавит свои параметры \`vk_app_id\`, \`vk_user_id\`, \`vk_ts\` и \`sign\`. Страница очищает адресную строку и по очереди проверяет \`VKWebAppInit\`, \`VKWebAppGetUserInfo\`, затем серверную HMAC-подпись.
5. Ожидаем экран «Успех: VK Bridge и серверная HMAC-подпись подтверждены». При неверном app ID/пользователе/времени/подписи — отказ. При недоступности библиотеки/хостинга — понятная ошибка без изменений данных игры.
6. Не присылайте URL с параметрами \`vk_…\` или \`sign\`, protected key, cookie Vercel или токены. Для отчёта достаточно скриншота **после** очистки URL, без персональных данных.

## Безопасность и ограничения

- Вход/выход и отображение состояния — единственная функция этой сборки.
- Клиент отправляет подписанные параметры только same-origin API через заголовок Authorization (ни в адресе API, ни в body, ни в localStorage).
- Никаких клиентских сумм, прогресса, платежей и сторонних аналитик.
- Обработка сервером использует \`VK_PROTECTED_KEY\` из **Preview** окружения Vercel, значение не записано в GitHub.
- VK launch-параметры технически присутствуют в исходном URL первого запроса от VK; они не показываются на странице. Не добавляйте сторонние скрипты, аналитику или доступные поисковой выдаче URL.
- В случае если Vercel не позволяет узкое исключение для preview на данном аккаунте — не нужно отключать защиту всего проекта. Используйте выделенную безопасную публичную тестовую среду с отдельным хостингом/доменом и собственным секретом, не трогая production.
- Реальный вход в клиенте ВК не проверялся автоматически: QA использует заглушку VK Bridge и тестовый HMAC.
- Сохранение прогресса нельзя включать без постоянного хранилища и механизмов против повторных начислений.
